# How AI was used

I built this with AI coding agents (every commit carries a Claude co-author trailer); I set the plan, reviewed each change and decided what landed. Documents came before code: requirements, data model, architecture, login, tRPC contracts, data generation and screen prototypes (`bc9f17d` … `21e7f0a`), so agents had a spec to build against and I had one to review against. `AGENTS.md` then fixed the coding rules and a planned file tree before the scaffold (`9ee5d6b`), later split into root rules and per-area guides so an agent loads only what its folder needs (`df5e0b9`). Rules that matter are mechanical, not prose: ESLint enforces import boundaries, single import sites, env access and colour tokens (`77f2252`, `7685c3a`), and the type system requires a transaction where one is needed (`a985d3f`).

Work went in small vertical slices, each a Conventional Commit that passes typecheck, lint and tests. Core rules landed test-first as red → green pairs, the red commit holding the failing test and a stub: signed cursors (`ee04ca5` → `8ca9b23`), keyset pagination (`b00735b` → `30bb529`), error mapping (`71558f3` → `22a548f`), employment dates (`6e4d3be` → `89fe1f6`), salary revisions (`ca838ca` → `5fe87f1`) and each report's numbers (e.g. `929bfb8` → `3bbe507`). Verification does not trust the code against itself: `db:verify` checks every report on the 10,000-employee seed against an independently computed manifest (`45c5fc1`), and CI runs unit, database and browser tests plus the verify on every push.

Separate review passes over finished slices found real issues, each fixed in its own commit: an open edit form could overwrite a refetched record (test `f4ba3ce`, fix `8f60ce7`), queries ran in parallel on one transaction connection (`c2d29de`), a router stitched a use case together instead of the operation owning it (`575793a`), and feature policy and duplicated rules had crept into shared code (`9bbfe7c`, `2504dbb`, `72fbba5`). Tests caught others, such as a sign-in redirect loop that only showed in a production build (`f7e29f7`) and stale-cursor handling (`105df06`).

## Where the AI needed correcting

- **Over-prescriptive plans.** The planned tree named files before their use was known. "Exactly `queries.ts` + `operations.ts` per report" pushed shared report SQL (filters, active selection, keyset comparisons) into one `reports/filters.ts`, later split (`1d52fb4`); report defaults sat in a shared `lib/product-defaults.ts` until each report owned them (`6fe69b4`); `trpc/router-types.ts` never had a consumer (`14e0a8f`). The rules were then rewritten around concepts: mechanism vs policy, operations own use cases, extract by concept not text (`c2a9781`, `b8c9741`).
- **Guides drift.** When implementation proved a guide wrong, the guide changed in the same commit: 63 of the 122 commits that built the app touch an `AGENTS.md` alongside code, e.g. the form baseline rule (`8f60ce7`), the transaction rule (`c2d29de`) and the use-case rule (`575793a`). The pagination pseudocode was rewritten to match the built helper (`5920b35`).
- **Length.** The requirements grew past the brief's one page and were trimmed, linking calculation detail to the contracts instead of restating it (`d0f6850`).
